# SEOと今後の方針（2026-09-30 相談メモ）

## 1. 現状の課題

- index.html に入っている文章は「Colors for the Fool」「タップして、一枚引く」程度で、meta description も OGP もない。
- カードの解釈（meanings.js）も色の物語（data/*/色.txt）も、クリックした後に JS の fetch で読み込み、ランダムに1つだけ表示している。
- Google は JS を実行して読むが、クリックしないと出てこない中身と、URLが1つしかないランダムな結果は検索に載らない。
- つまり、書いた文章（22枚 × 正逆の解釈、色の物語 約440本）がほぼ全部、検索エンジンから見えていない。

## 2. 静的ページ（ライブラリ）を作る

アプリはそのまま残し、SEO用のページを後から足す。

- ビルドスクリプト（例：scripts/build_static.py）で、次のページを静的HTMLに書き出す。
  - /cards/the-world/ … カードごとのページ（22ページ）。正位置・逆位置の意味と、色の一覧へのリンク。
  - /cards/the-world/gold/ … 色ごとのページ（約440ページ）。物語の本文とシーン画像。
- 各ページに、固有の title、description、OGP、構造化データ（Article）を付ける。
- sitemap.xml と robots.txt を作る。
- アプリで引いた結果の画面から、該当するカード／色のページへリンクする（シェア用の固定URLにもなる）。
- アプリが選ぶ色は、シーン画像があるものだけ。目標は366色で、閏年の日数にあわせた1年分（1日1色）とする。いまは各向き4色、合計176色。画像を足すとその色も候補に入る。画像のない色の文章はライブラリには残してよい。
- コンテンツは今まで通り data/ のテキストで管理し、ビルドし直せばページに反映される。
- ※ 公開先（S3＋CloudFront、Netlify など）によって、URLの形と出力先を決める。

### 全部公開しても「引く意味」は失われない

- タロットの意味は、もともと本やサイトで全部公開されている。人が引くのは「今の自分にどれが来たか」を知りたいから。
- 22枚 × 正逆 × 10色なので、一覧を読んでいても次に何が出るかは分からない。
- 役割分担：中身はライブラリで公開し、偶然の出会いはアプリで体験してもらう。
- 一覧があると、引いた後に他の色を読み比べられる／検索から来た人がアプリに入る／シェアしやすい、という利点がある。
- 検討事項：一覧で見せる絵の大きさ（画像検索の入口にしたいなら大きく、引いた瞬間の特別感を残すなら差をつける）。
- アイデア：引いたカードに一覧で印がつくようにすると、集める楽しみにもなる（Cookieの仕組みと相性が良い）。

## 3. 分かりやすさの改善

今のままだと「タロットで今日のラッキーカラーを占うサイト」だと伝わりにくい。

- 最初の画面では、サイト名とカードの裏面しか見えない。
- 2回目のタップの案内が「今日の色が開きます」で曖昧。「ラッキーカラー」という言葉が、物語の最後の段落まで出てこない。
- 物語が長いのに、ゴールが先に分からないので、途中で離れやすい。
- 右上の「残り◯枚」が何の数字か分かりにくい。

改善案：

- サイト名の下に一行「タロットで占う、今日のラッキーカラー」を入れる。
- 案内を「もう一度タップすると、今日のラッキーカラーが開きます」に変える。
- 物語の前に「今日のラッキーカラー：ゴールド」を色のチップや絵と一緒に先に見せ、最後の段落は答え合わせとして残す。
- title や見出しに「ラッキーカラー」「タロット」を入れる（「今日のラッキーカラー」「ラッキーカラー 占い」は検索が多い言葉）。

## 4. トップページの構成

上は簡潔に、下はボリュームがあってよい。下の部分はタップで畳む。

- 最初から HTML に書いておき、タップしたら JS で畳むのは SEO 上問題ない（訪問者も見ている内容なので隠しテキストにはならない）。
- 今は h1 が空のまま始まるので、トップの内容にちゃんとした h1 を持たせる。

### 上部（スマホの最初の画面に収める）

- サイト名：Colors for the Fool
- 一行説明：タロットで占う、今日のラッキーカラー
- カードの裏面と「タップして、一枚引く」

### 下部（タップすると畳まれる）

1. 遊び方（3ステップ）
   - ① カードを一枚引く（22枚の大アルカナ、正位置と逆位置）
   - ② カードの意味を読む
   - ③ もう一度タップすると、物語と一緒に今日のラッキーカラーが現れる
2. このサイトについて（コンセプト）：大アルカナそれぞれに10の色を結びつけ、神話・歴史・土地・道具の話をたどって一つの色に行き着く物語であること。
3. 色のシーンのギャラリー：絵を数枚並べ、ライブラリへリンク。
4. 今日の一篇：日替わりで物語を1本、冒頭から紹介（再訪の理由になる）。
5. 22枚のカード一覧：カード名と正位置・逆位置の意味を一行ずつ載せ、カードページへリンク（検索と内部リンクに一番効く）。
6. よくある質問：正位置と逆位置の違い／同じカードが出ない理由（Cookieで記録し、22枚引き終わると山が戻る）／毎日引いてもいいか。

ポイント：

- 最初の2〜3行で要点が分かり、あとは読みたい人が読む作りにする。
- h2 に「ラッキーカラー」「タロット」「大アルカナ」を自然に入れる。
- 説明の部分も、物語に合わせて少し詩的なトーンにする。
- スマホではカードとタップのボタンを最初の画面に収めたままにする。
- 畳むときは、すっと畳まれる動きにする。カードを裏に戻したときは、下の説明を再表示する。

## 5. 多言語化

### 英語版

- 作る価値が高い：タロットの検索は英語圏が圧倒的に大きい。サイト名もフォントも、すでに英語圏向け。
- シーン画像は言葉に依存しないので、絵がある色はそのまま使い回せる。目標は366色（1年分）。いまは各向き4枚、合計176色で、順次増やす。
- 英語圏の強いサイト（Labyrinthos、Biddy Tarot など）は意味の解説が中心で、「カード × 色の物語と絵」は他にない切り口。
- 翻訳ではなく、英語で別の文章を書いてよい（そのほうが自然で、英語圏で響く題材や検索のされ方に合わせられる）。
- 揃えておくもの：
  - カード × 色の組み合わせと、それぞれが象徴するテーマ（共通のメモを土台にし、各言語で自由に書く）。
  - 絵との対応（物語が絵に写っているものに触れるなら合わせる）。
  - 正位置・逆位置の構造。
- 最初の一歩：docs/解釈の作り方.txt の英語版の手引きを作る。
- ファイル例：data/the-world/gold.en.txt

### URLの分け方

- 同じURLで言語ごとに出し分けるのは、技術的には可能（Accept-Language、IP判定、JS切り替え）だが、SEOでは非推奨。Googleのクローラーは主にアメリカから言語設定なしで来るので、片方しかインデックスされない。
- / （日本語）と /en/ （英語）のようにURLを分け、hreflang で対応付ける（文章が違っても、同じカード × 色のページ同士なら対応付けてよい）。
- 言語が合わない人には、自動で飛ばさずバナーで案内する（自動で飛ばすとクローラーも飛ばされる）。
- トップページに x-default を指定する。

### 英語以外

- 候補：スペイン語・ポルトガル語（中南米、特にブラジル）、繁体字中国語（台湾・香港）、韓国語。
- 自分で読めない言語は質を確認できず、質の低いページを大量に出すとサイト全体の評価を下げかねない。
- 英語版を出して Search Console で数か月反応を見て、反応があれば同じ仕組みで追加する。

## 6. 進める順番

1. トップページの一行説明と、ラッキーカラーの見せ方を改善する。
2. トップページの下部コンテンツを作る。
3. 日本語版のライブラリ（静的ページ）と sitemap を作る。
4. 英語版の書き方の手引きを作り、英語版を作る。
5. Search Console で反応を見て、他の言語を検討する。
