# デザインの増やし方

様式を一つ足す手順です。入力は三つです。悪魔の PNG、吊るされた男の PNG、その様式を一言で言う名前です。例は「ベルギーのレース編み」です。

絵の正本は、`public` の外にある `design/<スラッグ>/` の PNG です。入力の悪魔から `design/design.md` にプロンプトを書き、残りの20枚と裏のプロンプトをファイルにします。吊るされた男は悪魔と同じく、入力の PNG を正本にします。画像は ChatGPT で作ります。素材が揃ってから、JPEG にし、各言語の HTML を書き、JavaScript の名簿に入れます。牌のページは、この手順では作りません。

言語を一つ足して、すでにある様式を訳す手順は [言語の増やし方](言語の増やし方.md) です。

クッキー `cftf-design` は言語をまたいで一つです。名簿に無い様式は、使っても引き画面が受け取りません。

## 1. 様式の種を書く

英語のスラッグを一つ決めます。例は `editorial-luxury` です。フォルダ名、`data-design`、クッキーの値がこれになります。

入力の PNG は二つです。`design/<スラッグ>/the-devil.png` と `design/<スラッグ>/the-hanged-man.png` に置きます。大きさはどちらも 1024×1536 です。プロンプトは悪魔の絵と、一言の名前から書きます。吊るされた男は、ここにプロンプトを書きません。

`design/design.md` の一覧に一行足し、`### <スラッグ>` の節を書きます。一覧の名前は、入力の一言です。節の画像は `design/<スラッグ>/the-devil.png` を指します。囲みの中は、次の順にします。

1. 縦長のカードであること。番号は上部中央、英語のタイトルは下部中央のバナー。余計な文字、透かし、署名は入れない。
2. その様式の段落。
3. `Scene for XV, THE DEVIL:` から始まる、悪魔の情景。

## 2. 残りのプロンプトを出す

`scripts/write_design_prompts.py` に、そのスラッグを登録します。

- 人物を牌のあいだで共有できる様式は、`WHO` と `LOCK` に書きます。
- 共有できない様式は、`SPECIAL` に牌ごとの情景を書きます。
- 裏は `BACK` に書きます。
- 様式の段落が、裏に人物や文字を呼び戻すときは、`BACK_HEADER_FIX` でその句を外します。

リポジトリのルートで実行します。

```sh
python3 scripts/write_design_prompts.py
```

`design/<スラッグ>/` に、残りの20枚のプロンプトと `back.txt` が書かれます。悪魔のプロンプトは `design.md` のまま残ります。吊るされた男のプロンプトは書きません。すでに絵がある牌は飛ばされます。

## 3. ChatGPT で残りの絵を作る

`design.md` の悪魔、20枚のプロンプト、`back.txt` が揃ってから、ChatGPT で絵を作ります。参照画像は入力の `the-devil.png` です。悪魔と吊るされた男は、入力の PNG を正本にします。ここでは作り直しません。

できた絵は、同じ `design/<スラッグ>/` に PNG で置きます。ファイルは20枚の牌と `back.png` です。例は `the-fool.png` です。`back.png` はカードの裏です。大きさは 1024×1536 です。ここまでが素材です。

## 4. サイト用の JPEG にする

素材のあとです。ここから JPEG、各言語の HTML、JavaScript の名簿の順です。

`design/<スラッグ>/` の PNG を JPEG にします。22枚と裏を `public/design/<スラッグ>/` に置きます。ファイル名は牌のスラッグと `back.jpg`、`the-devil.jpg` です。例は `the-fool.jpg` です。

一覧の見本は、悪魔の JPEG を `public/design/<スラッグ>.jpg` にも置きます。サイトの根にある言語の一覧は、このファイルを直に指します。`prefix` のある言語の一覧は `../../design/<スラッグ>.jpg` を指します。

## 5. すでにある言語のページを写す

デザイン一覧がある言語ごとに、既存の様式の `index.html` を、新しいスラッグのディレクトリへ写します。絵のファイルは写しません。

- 根の言語は `public/design/<既存>/index.html`
- それ以外は `public/<prefix>/design/<既存>/index.html`

一覧がまだ無い言語は、ここでは作りません。その言語を足すときに、[言語の増やし方](言語の増やし方.md) に沿って、その時点の様式をまとめて訳します。

変えるものは、スラッグそのもの、見出し、リード、画像の alt、`data-design`、一覧へ戻るリンクの `#<スラッグ>`、canonical、`og:url`、`og:image`、hreflang です。hreflang は、この様式のページがある言語を `data/languages.json` の順に並べ、それぞれの `hreflang` を使います。`x-default` は根の言語の URL です。

リードは要約しません。その言語の既存ページと同じ語りにします。キャプションの英語名は、その言語の `latinSubtitle` に合わせます。true なら牌名のあとに英語名を添え、false なら牌名だけにします。

根の言語の絵は `the-fool.jpg` のように、ページの隣を指します。`prefix` のある言語は `../../../design/<スラッグ>/<牌>.jpg` を指します。`deck.css`、`lang.js`、`use.js` は `public/design/` のまま共有します。

## 6. 一覧と、使うための名簿に足す

デザイン一覧がある言語のすべてに、末尾として足します。根は `public/design/index.html`、ほかは `public/<prefix>/design/index.html` です。目次と図の両方に、同じスラッグで入れます。番号は、その一覧の最後の番号の次です。既存の番号は動かしません。

次の三つの名簿には、アルファベット順で同じスラッグを足します。

- `public/app.js` の `DESIGNS`
- `public/design/use.js` の `DESIGNS`
- `scripts/build_library.py` の `DESIGN_STYLES`

## 7. 生成して確認する

リポジトリのルートで実行します。

```sh
python3 scripts/build_library.py
```

`index.html` がある様式だけがサイトマップに入ります。生成はデザインの本文、言語メニュー、hreflang を書き換えません。この生成は本番へは出しません。本番へ出す手順は第8節です。

プレビューは、リポジトリのルートで `python3 -m http.server 8741` を動かしてから、`http://127.0.0.1:8741/public/design/` を開きます。確認することは四つです。

- 一覧の末尾からその様式を開くと、22枚と裏の絵が出る
- 言語メニューが、この様式を持つ言語のあいだを開く
- 戻るリンクが、一覧のその様式へ戻る
- 使うボタンが、そのスラッグを `cftf-design` に入れる。別の言語の引き画面でも、同じ絵になる

使うボタンは、プレビューのクッキーを変えてよいときだけ押します。

## 8. 本番へ出す

プレビューで確認したあと、頼まれたときだけ本番へ出します。バケットは `s3://colorsofthefool-engawa5656`、リージョンは `ap-northeast-1`、CloudFront のディストリビューションは `E19FXFPQJ46V1` です。同期に `--delete` は付けません。`days/` は対象にしません。

上げるファイルは、その様式の JPEG（`public/design/<スラッグ>/` の22枚と `back.jpg`、一覧の見本 `public/design/<スラッグ>.jpg`）、デザイン一覧がある言語の一覧と様式の `index.html`、`public/app.js`、`public/design/use.js`、`public/sitemap.xml` です。

Content-Type は、HTML が `text/html; charset=utf-8`、JavaScript が `text/javascript; charset=utf-8`、JPEG が `image/jpeg`、サイトマップが `application/xml` です。Cache-Control は `public, max-age=300` です。

同じ反映で、トップの日付も当日にします。リポジトリの `public/index.html` は上げません。上のファイルを入れたあと、Lambda `colorsofthefool-instagram` に `refreshHome` を渡します。

```sh
aws lambda invoke \
  --function-name colorsofthefool-instagram \
  --region ap-northeast-1 \
  --cli-binary-format raw-in-base64-out \
  --cli-read-timeout 180 \
  --payload '{"refreshHome": true}' \
  /tmp/cftf-home.json
```

この呼び出しは Instagram へは投稿しません。本番のトップにすでにある `.today` の一行を、実行した日の日本時間へ書き換え、`days/その日/` を指します。その日のページが無いときは、同じ呼び出しが `days/その日/index.html` を作り、前日のページに翌日へのリンクを足します。戻り値の `date` が当日になってから、キャッシュを消します。

消すパスは、上げたデザインの URL と、`/` と `/index.html` です。その日のページを新しく書いたときは、`/days/その日/` と前日のページも消します。
