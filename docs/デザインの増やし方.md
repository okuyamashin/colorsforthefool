# デザインの増やし方

様式を一つ足す手順です。絵は `public/design/` に一組だけ置きます。ページは、すでにデザイン一覧がある言語のぶんだけ、既存の様式を写して手で直します。牌のページは、この手順では作りません。

言語を一つ足して、すでにある様式を訳す手順は [言語の増やし方](言語の増やし方.md) です。

クッキー `cftf-design` は言語をまたいで一つです。名簿に無い様式は、使っても引き画面が受け取りません。

## 1. 様式の種を書く

英語のスラッグを一つ決めます。例は `editorial-luxury` です。フォルダ名、`data-design`、クッキーの値がこれになります。

`design/design.md` の一覧に一行足し、`### <スラッグ>` の節を書きます。見本は悪魔です。囲みの中は、次の順にします。

1. 縦長のカードであること。番号は上部中央、英語のタイトルは下部中央のバナー。余計な文字、透かし、署名は入れない。
2. その様式の段落。
3. `Scene for XV, THE DEVIL:` から始まる、悪魔の情景。

## 2. 残りのプロンプトを出す

`scripts/write_design_prompts.py` に、そのスラッグを登録します。

- 人物を牌のあいだで共有できる様式は、`WHO` と `LOCK` に書きます。
- 共有できない様式は、`SPECIAL` に牌ごとの情景を書きます。
- 裏は `BACK` に書きます。
- 様式の段落が、裏に人物や文字を呼び戻すときは、`BACK_HEADER_FIX` でその句を外します。

リポジトリのルートで実行します。

```sh
python3 scripts/write_design_prompts.py
```

`design/<スラッグ>/` に、悪魔以外の22枚と `back.txt` が書かれます。悪魔のプロンプトは `design.md` のまま残ります。すでに絵がある牌は飛ばされます。

## 3. 絵を置く

プロンプトから、22枚、裏、悪魔を出します。置き場所は `public/design/<スラッグ>/` です。ファイル名は牌のスラッグと `back.jpg`、`the-devil.jpg` です。例は `the-fool.jpg` です。大きさは 1024×1536 です。

一覧の見本は、悪魔の絵を `public/design/<スラッグ>.jpg` にも置きます。サイトの根にある言語の一覧は、このファイルを直に指します。`prefix` のある言語の一覧は `../../design/<スラッグ>.jpg` を指します。

## 4. すでにある言語のページを写す

デザイン一覧がある言語ごとに、既存の様式の `index.html` を、新しいスラッグのディレクトリへ写します。絵のファイルは写しません。

- 根の言語は `public/design/<既存>/index.html`
- それ以外は `public/<prefix>/design/<既存>/index.html`

一覧がまだ無い言語は、ここでは作りません。その言語を足すときに、[言語の増やし方](言語の増やし方.md) に沿って、その時点の様式をまとめて訳します。

変えるものは、スラッグそのもの、見出し、リード、画像の alt、`data-design`、一覧へ戻るリンクの `#<スラッグ>`、canonical、`og:url`、`og:image`、hreflang です。hreflang は、この様式のページがある言語を `data/languages.json` の順に並べ、それぞれの `hreflang` を使います。`x-default` は根の言語の URL です。

リードは要約しません。その言語の既存ページと同じ語りにします。キャプションの英語名は、その言語の `latinSubtitle` に合わせます。true なら牌名のあとに英語名を添え、false なら牌名だけにします。

根の言語の絵は `the-fool.jpg` のように、ページの隣を指します。`prefix` のある言語は `../../../design/<スラッグ>/<牌>.jpg` を指します。`deck.css`、`lang.js`、`use.js` は `public/design/` のまま共有します。

## 5. 一覧と、使うための名簿に足す

デザイン一覧がある言語のすべてに、末尾として足します。根は `public/design/index.html`、ほかは `public/<prefix>/design/index.html` です。目次と図の両方に、同じスラッグで入れます。番号は、その一覧の最後の番号の次です。既存の番号は動かしません。

次の三つの名簿には、アルファベット順で同じスラッグを足します。

- `public/app.js` の `DESIGNS`
- `public/design/use.js` の `DESIGNS`
- `scripts/build_library.py` の `DESIGN_STYLES`

## 6. 生成して確認する

リポジトリのルートで実行します。

```sh
python3 scripts/build_library.py
```

`index.html` がある様式だけがサイトマップに入ります。生成はデザインの本文、言語メニュー、hreflang を書き換えません。この生成は本番へは出しません。

プレビューは、リポジトリのルートで `python3 -m http.server 8741` を動かしてから、`http://127.0.0.1:8741/public/design/` を開きます。確認することは四つです。

- 一覧の末尾からその様式を開くと、22枚と裏の絵が出る
- 言語メニューが、この様式を持つ言語のあいだを開く
- 戻るリンクが、一覧のその様式へ戻る
- 使うボタンが、そのスラッグを `cftf-design` に入れる。別の言語の引き画面でも、同じ絵になる

使うボタンは、プレビューのクッキーを変えてよいときだけ押します。
